# Portfolio

Master-репозиторий, который собирает портфолио из других ваших GitHub-репо
и публикует через GitHub Pages по адресу
**https://mbyourk1337.github.io/Portfolio/**

## Как это работает

1. Каждый проект — отдельный репозиторий. Складываете туда что угодно:
   фото, чертежи, PDF, DOCX, CAD-модели, видео, архивы — структура
   произвольная.
2. Ставите репо топик раздела, в который проект должен попасть:

   | Топик | Раздел |
   |---|---|
   | `portfolio-llm` | Локальные LLM и автоматизация |
   | `portfolio-cad` | CAD и инженерия |
   | `portfolio-games` | Игры и геймдизайн |
   | `portfolio-other` | Остальные |

   Если у репо несколько топиков сразу, побеждает раздел, который выше
   в `src/data/sections.ts`. Репо без топика раздела, но со старым
   `portfolio-project`, попадает в «Остальные».
3. В корень репо кладёте три необязательных текстовых файла:
   - **`name`** — название проекта (первая строка файла; можно по-русски,
     с пробелами и любыми символами).
   - **`desc`** — описание проекта (любой длины, без оформления, переносы
     строк сохраняются).
   - **`tags`** — технологии и инструменты, по строке на тег. На карточке
     видно первые три (остальные схлопываются в «+N»), на странице
     проекта — все. Маркеры `-` / `*` в начале строки игнорируются, дубли
     в разном регистре схлопываются, максимум — 6 тегов.

   Расширения `.md` / `.txt` тоже работают — `name.txt`, `desc.md`, `tags.txt`.
4. Фолбэки, если файлов нет: для названия — причёсанное имя репо, для
   описания — поле **About** на GitHub (там лимит 350 символов),
   для тегов — пусто.
5. Master-репо при сборке находит все ваши репо с топиками разделов,
   читает их деревья и генерирует:
   - на главной — плитки направлений и последние 6 проектов;
   - на странице раздела (`/cad/`, `/llm/` …) — сетку карточек этого
     направления;
   - на странице проекта — полное описание, теги, карусель из всех
     картинок и список остальных файлов со ссылками на скачивание.

Никаких `project.json` или метаданных не нужно — только `name`, `desc`
и `tags` (все опциональны), всё остальное берётся автоматически.

### Состояние проекта

Статус задаётся отдельным топиком и не влияет на раздел — проект остаётся
там, куда его отправил `portfolio-*`-топик.

| Топик | Плашка на сайте |
|---|---|
| `status-dev` | В разработке |
| `status-proto` | Прототип |
| `status-live` | Работает |

```bash
# например, отметить проект как прототип
gh repo edit --add-topic status-proto
```

Если статус-топика нет, плашки нет. Если стоит несколько — приоритет:
`status-live` → `status-proto` → `status-dev`.

## Как добавить новый проект

```bash
# 1. Завести папку для проекта (название = имя будущего репо на GitHub)
mkdir my-new-project && cd my-new-project

# 2. Положить в корень текстовые файлы — name, desc и (по желанию) tags:
echo 'Название проекта на русском' > name

cat > desc <<'EOF'
Что это за проект, в одном-двух абзацах.
Можно с переносами строк — они сохранятся.

— буллеты тоже работают
— главное, без markdown
EOF

printf 'SolidWorks\nSiemens NX\nрасчёты\n' > tags

# 3. Положить внутрь что угодно: photos/, docs/, models/, video.mp4, drawing.pdf …
#    Структуру делать удобно так:
#      photos/   — фото и рендеры (имена с префиксом 01-, 02- задают порядок)
#      docs/     — PDF, DOCX
#      models/   — CAD: .SLDPRT .SLDASM .STEP .STL .DWG …
#      videos/   — .mp4 .mov .webm
#      archives/ — .zip полные пакеты
#    Но это рекомендация, не требование.

# 4. Запушить как новый публичный репо
git init -b main
git add .
git commit -m "init"
gh repo create my-new-project --public --source=. --push

# 5. Поставить топик раздела — llm / cad / games / other
gh repo edit --add-topic portfolio-cad

# 6. По желанию — топик состояния
gh repo edit --add-topic status-proto

# 7. Триггернуть пересборку портфолио (или подождать ночной крон)
gh workflow run "Deploy to GitHub Pages" -R mbyourk1337/Portfolio
```

Через ~1 минуту карточка появится на сайте. Картинки автоматически попадут в
карусель, всё остальное — в список «Файлы» внизу страницы проекта.

### Как изменить название, описание или теги проекта

Отредактируйте `name`, `desc` или `tags` в проект-репо и запушьте — на
следующем билде обновится.

### Как изменить порядок проектов

Не нужно — отсортированы по дате последнего обновления, свежие сверху.
Хотите вытащить проект наверх — сделайте в нём пуш (любой).

### Как изменить порядок картинок в карусели

Картинки сортируются по пути в репо. Префиксы `01-`, `02-` … работают как ожидается:
```
photos/01-cover.jpg
photos/02-detail.jpg
photos/03-render.jpg
```

### Как перенести проект в другой раздел

Поменяйте топик репо: снимите старый, поставьте новый. При нескольких
топиках раздел выбирается по порядку в `src/data/sections.ts`.

### Как добавить, переименовать или скрыть раздел

Все разделы живут в `src/data/sections.ts`. Порядок в массиве = порядок
на главной.

```ts
{
  id: 'llm',                       // часть URL: /llm/
  title: 'Локальные LLM и автоматизация', // заголовок на сайте
  topic: 'portfolio-llm',          // топик, которым проект привязан к разделу
  lead: 'Одна строка о направлении — на плитке и в шапке раздела',
}
```

Добавили объект — появилась страница `/<id>/` и плитка на главной.
Раздел без проектов на главной не показывается; чтобы показать пустой,
допишите `hideWhenEmpty: false`.

Проект всегда лежит ровно в одном разделе — если он на стыке направлений,
это решается тегами, а не дублированием.

## Лимиты

- **100 МБ — максимум на один файл в обычном пуше.** Большие файлы заливайте
  в **Releases** репо (до 2 ГБ на ассет) — они появятся в списке «Файлы»
  только если положены в дерево репо. Для Releases-ассетов пока ставьте
  ссылку в README или в About.
- **5 ГБ мягкий / 100 ГБ жёсткий лимит на репо** — поэтому каждый проект
  отдельный репо.
- **GitHub Pages: 1 ГБ на сайт, 100 ГБ траффика/мес** — у master-репо
  только HTML/CSS/JS, картинки и файлы остаются в проект-репо и грузятся
  напрямую с raw.githubusercontent.com.

## Когда обновляется сайт

- **Push в `main` master-репо** — сразу.
- **Каждую ночь** в 03:17 UTC — подхватывает изменения проект-репо.
- **Ручной запуск:** `Actions → Deploy to GitHub Pages → Run workflow`,
  или из терминала:
  ```bash
  gh workflow run "Deploy to GitHub Pages" -R mbyourk1337/Portfolio
  ```
- **Авто-триггер из проект-репо** (опционально, чтобы не ждать кроном):
  положите в проект-репо файл `.github/workflows/notify.yml`:

  ```yaml
  name: Notify portfolio
  on:
    push:
      branches: [main]
  jobs:
    notify:
      runs-on: ubuntu-latest
      steps:
        - env:
            PAT: ${{ secrets.PORTFOLIO_DISPATCH_TOKEN }}
          run: |
            curl -sS -X POST \
              -H "Authorization: Bearer $PAT" \
              -H "Accept: application/vnd.github+json" \
              "https://api.github.com/repos/mbyourk1337/Portfolio/dispatches" \
              -d '{"event_type":"project-updated"}'
  ```

  И положите в Settings → Secrets → Actions проект-репо секрет
  `PORTFOLIO_DISPATCH_TOKEN` — Personal Access Token с правом `repo` на
  master-репо.

## Локальная разработка master-репо

```bash
npm install
npm run dev
```

Без `GITHUB_TOKEN` — 60 запросов/час к API, чего хватает на пару
перезагрузок страницы. С токеном — 5000/час (у поиска отдельный лимит,
30 запросов/мин). Токен кладётся в `.env` — файл уже в `.gitignore`:

```
GITHUB_TOKEN=github_pat_xxx
```

Достаточно fine-grained токена с доступом `Public repositories (read-only)`.
После правки `.env` перезапустите dev-сервер.

Ответы GitHub кэшируются на время жизни процесса, поэтому свежие правки
в проект-репо локально видны только после перезапуска `npm run dev`.

## Структура

```
src/
├── data/
│   ├── sections.ts                  # разделы сайта: порядок, топики, описания
│   ├── statuses.ts                  # статусы проектов: status-dev / proto / live
│   └── profile.ts                   # «Обо мне», навыки и образование
├── lib/
│   ├── github.ts                    # фетч репо, дерева файлов, name/desc/tags
│   └── plural.ts                    # «1 проект / 2 проекта / 5 проектов»
├── components/
│   ├── SectionCard.astro            # плитка направления на главной
│   ├── ProjectCard.astro            # карточка проекта
│   └── Carousel.astro               # карусель картинок
├── pages/
│   ├── index.astro                  # главная: профиль, направления, проекты
│   ├── [section]/index.astro        # страница раздела (/cad/, /llm/ …)
│   └── projects/[slug].astro        # страница проекта
└── styles/global.css

.github/workflows/deploy.yml         # билд + деплой на Pages
```
